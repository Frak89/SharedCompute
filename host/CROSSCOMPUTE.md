# CrossCompute + MultiAgent (Windows)
Use the CrossCompute Actions artifact. Extract its contents. Launch SharedCompute-CrossCompute.exe. Existing Android APK remains unchanged: this coordinator uses localhost and explicitly entered LAN OpenAI-compatible endpoints, no ADB for model discovery. Remote model APIs must already run on trusted endpoints; use TLS or a separately secured network. This release does not change the RPC Android transport (it still uses ADB); the ADB-free authenticated RPC tunnel is a separate feature.
Default discovery includes local Ollama :11434, LM Studio :1234, SharedCompute :8081 and llama-server :9931. Start the engines with models accessible first. No GGUF files are copied or imported here.
Select one or more models and optional master. Benchmark selected models explicitly (sequential, skips local models if available Windows RAM is below 1024 MiB). Counts come from actual server completion_tokens; speeds are end-to-end including model loading and network, not exact decode-only rates. Unknown counts stay unknown. Results are session-only. Benchmarks may still load several resident models sequentially, so stop/unload unnecessary engines yourself; no automatic eviction of third-party processes.
Modes:
- AUTO: fastest measured selection (manual master overrides); independent tasks separated by a line containing --- use a task scheduler.
- SPEED: one model, fastest measured or selected master; no invented combined speed.
- QUALITY: MultiAgent review, user choice, final approval.
- PARALLEL: 2–16 independent tasks separated by ---; one model per IP/loopback group by default. Explicit same-device overlap option is risky with low RAM. Remote aliases may describe the same physical hardware; physical topology must be verified by user. Outputs are kept separate and ordered.
- LOW RAM: use only the selected/automatic master; choose a small GGUF yourself. Not a hard RAM cap.
- HYBRID: MultiAgent with a prestarted RPC-backed llama-server on :8081 when available and Auto master; endpoint existence alone does not prove RPC is in use.
The native speculative launcher (PowerShell) uses the pinned llama.cpp flags to start the original local GGUF with a compatible draft GGUF or MTP head. Example: .\Start-Speculative.ps1 -Server E:\CYBER_AI\LLAMA_CPP\llama-server.exe -Model E:\CYBER_AI\MODEL\model.gguf -Draft E:\CYBER_AI\MODEL\draft.gguf. Only use -MTP for compatible models with the required MTP tensors; actual acceleration must be measured. It does not implement token-level speculation across Ollama and llama.cpp, which their chat APIs do not expose. No model duplication. No automatic download. Stop an existing server on the chosen port first. 
MultiAgent and CrossCompute tests mock APIs; hardware validation remains necessary.
