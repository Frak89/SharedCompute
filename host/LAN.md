# SharedCompute 1.1 — direct Wi-Fi, no ADB
Use matching Android APK and Windows llama-server from the same revision. Extract the CrossCompute artifact too. Launch SharedCompute-LAN-Host.exe (GUI). Keep all files on the SSD if you wish. No raw RPC listener is exposed to the network; Android listens on TLS TCP 50552, with a pinned certificate and a random 256-bit secret renewed on each activation. The Windows API and internal RPC forwards bind only localhost. Use a trusted private network; don't port-forward Android. Keep pairing lines secret. IP list and certificate/token are displayed on the phone; select/copy one IP line for each device (same Wi-Fi) and transfer securely to the PC. No automatic LAN discovery or QR yet. Stop the node to revoke its token. Activate Android while charging, start with conservative RAM and CPU settings. The host UI selects the existing llama-server executable, original GGUF, offload layer count and context. Once the server loads, CrossCompute discovers localhost:8081. Never assume a large GGUF fits just because several nodes are connected. The RAM budget is a watchdog rather than a hard allocation. Android background operation, Wi-Fi permission, TLS handshake, memory allocation and actual inference require real device tests. APK may require uninstall of older debug build if signing differs between CI runners. Existing legacy PowerShell ADB launcher remains optional, not required for the LAN path.
